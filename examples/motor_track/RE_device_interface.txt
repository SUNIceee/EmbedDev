1. The generated source defines the six application functions, motor_l, motor_r, motor_pid_l/r, target_speed_pid, posloop_pid, target_speed, and clk. It includes its own generated header using the method output protocol. No fixed generated-header filename is prescribed. The supplied declarations specify ABI, types, enums and storage ownership. The original motor.h belongs to a different omni-wheel project and is not supplied.
2. The environment defines motor_env and fills it before calls. angle is finite degrees in[-20,20]; speeds/duties finite, counts in the ranges in R,0<=rptsn_num<=128, points finite. For the geometry branch the chosen y difference is nonzero. enum values are declared valid values. No concurrent mutation occurs during a call. Positions are arbitrary track-coordinate units and their ratio is dimensionless. Encoder speed and target speed use the same fixed abstract speed unit; total/target_encoder use pulses.
3. Initial motor_env is supplied by the caller, not chosen by generated code. A neutral runnable environment typically has laser_angle90, no flags, inductance sum>=60. These are environmental states, not functions the generator must synthesize.
4. PWM channels0/1 are left forward/reverse,2/3 right forward/reverse. pwm_init records channel, frequency inHz and duty. pwm_duty records duty units0..50000. These fixed helpers update per-channel output observations; no physical timer/register access is generated. Use four calls per init/control, one per channel. Order among four writes is unrestricted; assessment checks complete final complementary outputs and correct channel identity, not switching dead time.
5. Missing original PID dependencies are supplied as fixed, deterministic helper contracts. pid_solve(p,e) updates p.out_i=clamp(p.out_i+p.ki*e,-p.max_integral,p.max_integral), computes p.kp*e+p.out_i+p.kd*(e-p.last_error), sets p.last_error=e, and returns that sum clamped to +/-p.max_output. No elapsed-time factor is applied. The helper is not to be reimplemented in the generated pair.
6. bangbang_pid_solve(p,e) records p.last_error=e and returns clamp(1000*e,-50000,50000), an increment to existing duty. changable_pid_solve(p,e) records p.last_error=e and returns clamp(250*e,-2000,2000), an increment. These fixed coefficients fill absent dependencies for this shared task; they are not claimed as measured or recovered upstream controller behavior. Normal speed PID gains7021/10/0, target PID5/0/30 with output cap5, and position PID200/0/0 are from the supplied source/SRS. No hidden original macro implementation is assumed.
7. The caller explicitly invokes the planning stage and/or actuation stage. Unlike the source's hidden speed_control call inside motor_control, this task has separate public stages so MODE_POSLOOP and each PID mode are actually testable. The same stage contract applies to every method. Host evaluation does not assert equivalence to the complete original firmware or hardware control performance.
8. PWM, PID, and environment functions are fixed by the evaluator; do not define them, create a main function, or emit tests/expected results.
