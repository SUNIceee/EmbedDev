DiscoBot Test-Compatible Software Requirements Specification
Version: Test-Compatible v3 (Comprehensive Host-Verifiable)
Based on: DiscoBot-test-comprehensive.json (DB-001 through DB-125)

================================================================================
1. Goals and acceptance principles
================================================================================

This firmware runs on STM32F407 Discovery using the STM32 Standard Peripheral Library (SPL). It receives single-byte movement commands through USART1/XBee, drives two DC motors on PA1 through PA4 via L293D, acquires acceleration, internal temperature, and hardware random numbers, and provides buttons, LEDs, a circular buffer, a task scheduler, and interrupt handling.

DiscoBot-test-comprehensive.json is an input/answer table, not an executable test program. This document converts its 125
valid cases into deterministic C11 calling contracts. The host version must expose hardware effects through GPIOA_output, GPIOD_output,
GPIOA_IDR, SysTick_reload, USART TX log, and related state; empty comments must not replace initialization,
GPIO writes, interrupt transmission/reception, or the startup sequence.

Covered modules: car (motor control) / main (command dispatch + button debounce + attitude calculation + LEDs) / accelerometers (LIS3DSH) / temperature (ADC1) / RNG / Task (timed_task 25-slot scheduler) / usart (USART1 + circular buffer + interrupt) / circarray (complete circular-array API) / funcs1.s (ARM assembly)

================================================================================
2. Hardware configuration
================================================================================

- MCU：STM32F407VG，SystemCoreClock=168000000 Hz
- SysTick: SysTick_Config(SystemCoreClock/1000)=168000 ticks, exactly 1ms, msTicks++
- USART1: PB6=TX, PB7=RX, 9600-8N1, RXNE interrupt, NVIC preempt=0/sub=0
- Motors: PA1~PA4, push-pull outputs, pull-up, 25MHz; direct L293D connection (no PWM, full speed)
- LEDs: PD12~PD15 (orange/green/red/blue), controlled by BSRRL/BSRRH
- Button: PA0 input (active-high logic in this experiment: high=pressed, low=released; the target adapter handles external pull-ups/pull-downs)
- Accelerometer: onboard LIS3DSH, TM-library wrapper, +/-2G sensitivity with 50Hz filter, SPI1
- Temperature: STM32F4 internal sensor, ADC1 12bit/continuous/prescaler8/sample144cycles
- RNG: STM32F4 hardware RNG (AHB2 clock), DRDY polling

================================================================================
3. System initialization (DB-111~115)
================================================================================

main() startup order (strictly required):
SystemInit() → init_systick() → init_LED_pins() → init_button() →
init_accelerometers() → init_rng() → init_temperature_sensor() →
init_GPIO_A1A2A3A4_output() → init_usart1(9600) →
usart1_send("UART1 Initialized. @9600bps\r\n") -> while(1) main loop

- init_systick calls SystemCoreClockUpdate() and then SysTick_Config(SystemCoreClock/1000)=168000
- Nonzero SysTick_Config return value (error) -> infinite while(1){} loop
- init_button: enable GPIOA clock and configure PA0 as INPUT (floating input; initialize host input low/released)

#define MAXNUMTASKS 25

void add_timed_task(void (*myfunc)(void), float interval_sec);
  // Scan timed_tasks[0..24] for the first NULL slot. Set task=myfunc, msinterval=(long)(interval*1000), last_called=0, numcalls=0.

  // Scan 25 slots: if task!=NULL and msTicks>=last_called+msinterval -> task() -> last_called=msTicks -> numcalls++.
  // Several tasks may trigger on the same tick; execute in slot order. Skip NULL slots.
  // BUG: when msTicks (uint32_t) overflows, msTicks<last_called+msinterval may cause missed triggers.

void printtimes(void);
  // Scan 25 slots: non-NULL -> printf("t{i}=%d", numcalls).

  // No remove_timed_task() function. Manually setting task=NULL effectively removes it.

10. USART -- interrupt-driven USART1 (DB-073~090)
================================================================================

void init_usart1(int baud);
  // baud==0 -> baud=9600 plus warning. GPIOB6(TX AF)+PB7(RX AF): push-pull/pull-up/100MHz.
  // USART: 8N1, no flow, TX+RX. Enable USART_IT_RXNE interrupt. NVIC preempt=0/sub=0.
  // initCircArray(&msg, 200) creates the receive buffer. USART_Cmd(USART1,ENABLE).
  // A comment says "Enable clock for GPIOA" but GPIOB is actually enabled (documentation bug; code is correct).

void USART1_IRQHandler(void);
  // RXNE -> c=USART1->DR -> buf_putbyte(&msg,c). Buffer full -> return 0 -> data lost.
  // TXE and others -> ignored (TX is performed by polling).

void usart1_send(volatile char *s);
  // while(*s): while(!(USART1->SR&0x40)){} wait TXE→USART_SendData(*s++)。
  // No timeout: USART1 disabled -> infinite loop.

uint8_t usart1_read(void);
  // = buf_getbyte(&msg). Empty -> 0. Note: 0 is indistinguishable from actual 0x00 data.

char usart1_readc(void);
  // = (char)buf_getbyte(&msg). 0xFF -> -1 (signed overflow). In main, read>=0 rejects valid 0xFF.

uint32_t usart1_available(void);
  // = buf_available(&msg) = n_w - n_r。

13. Boundary cases and stress points (DB-116~125)
================================================================================

- L293D: never emit IN1=IN2=1 (safety).
- Instant motor reversal has no dead time (~ns scale) and is generally safe.
- UART has no framing/checksum: noise may trigger random commands.
- UART has no ACK/NAK feedback.
- ADC continuous mode: SoftwareStartConv in read_temperature_sensor is redundant but harmless.
- buf_full remains correct when uint32_t n_w overflows (modulo behavior unchanged).
- usart1_send TXE wait has no timeout -> USART1 disabled -> infinite loop.
- RNG DRDY wait has no timeout -> RNG failure -> infinite loop.
- timed_task has no task-removal API, priority, or preemption; a long task blocks later ones.
- usart1_readc 0xFF->-1 is a signed-overflow pitfall.

15. Host verification and deterministic inputs
================================================================================

When DISCOBOT_TARGET is undefined, provide the following deterministic models:
- GPIOA_output[1..4] stores motor pins, GPIOD_output[12..15] stores LEDs; pin values may only be 0 or 1;
- GPIOA_IDR stores button input; discobot_set_button_level modifies only bit0;
- discobot_set_accelerometer_raw sets three raw milli-g values; read_accelerometers divides them by 1000;
- discobot_set_adc_raw sets the next temperature ADC value; follow the formula in Section 7 exactly;
- discobot_set_rng sets DRDY and the return value; ready=false represents hardware blocking, but host tests must not actually deadlock;
- discobot_usart1_inject_rx sets DR/RXNE, then executes the same USART1_IRQHandler logic;
- usart1_send appends characters in order to usart1_tx_log and maintains usart1_tx_length;
- dispatch_uart_command calls flookup immediately for 0..8; invalid, negative, and empty reads never change motor state;
- main_loop_iteration is the single-step host equivalent of while(1); production code must not define main();
- init_system strictly follows the DB-114 order and sends the exact string
  "UART1 Initialized. @9600bps\r\n"; do not change the text.

Emit independent self-tests in a separate file, not within the production implementation. All allocated memory must be releasable; null pointers, invalid
indices, and full buffers must return safely. Preserve historical behavior explicitly described by the tests (such as no UART framing protocol, no task-
removal API, and unused speed arguments); do not 'improve' it into a different protocol or PWM architecture.
